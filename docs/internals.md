# Internal Table Conventions

> [← Back to overview](../README.md)

These are **internal conventions for the component's own tables** — they do NOT affect your application tables.

## Standard Fields (all component tables)

| Column | Type | Purpose |
|---|---|---|
| `id` | BIGINT | Physical primary key, generated by the `sequence` component (no AUTO_INCREMENT) |
| `gmt_create` | TIMESTAMP | Creation time (auto DEFAULT CURRENT_TIMESTAMP) |
| `gmt_modified` | TIMESTAMP | Modification time (auto ON UPDATE CURRENT_TIMESTAMP) |

## Why No AUTO_INCREMENT

IDs are pre-generated by the snowflake generator before INSERT:
- IDs are available before the row hits the database (useful for cross-service references and event payloads)
- No auto-increment lock contention under high concurrency
- Globally unique across all services (workerId lease guarantees no collision)

## Tables Created

| Table | Component | Keys |
|---|---|---|
| `sys_sequence` | sequence | PK(id), UNIQUE(service_name) |
| `async_command` | async-command | PK(id), KEY(status,next_run_at), KEY(cmd_type,biz_key), KEY(claim_token) |
| `starsite_lock` | lock | PK(id), UNIQUE(lock_name) |

All tables use `CREATE TABLE IF NOT EXISTS` (idempotent). Disable with `init-ddl: false` if your DBA manages schema.
